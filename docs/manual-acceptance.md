# Manual regression acceptance matrix

Use this concise smoke matrix after a change touches the named area, and run it in full before merging a milestone that affects the desktop application. It captures the durable manual regression coverage established during Milestones 2 and 3.

Automated tests remain network-isolated and must never submit a paid provider request. Any live generation check is a deliberate human-only action and is not required for refactor acceptance.

| Area | Manual acceptance path | Expected result |
| --- | --- | --- |
| Project lifecycle | Create, close, reopen, switch between two projects, then restart ReelForge. After an interrupted save leaves recovery data, restart once and open the recovered working state, then repeat and discard recovery. | The last project reopens; project-specific selection/workspace state does not leak between projects; recent projects remain usable. Recovery is explicitly offered, never auto-activated, and opening it leaves the committed project unchanged until Save; discarding it keeps the committed project and retires the candidate. |
| Project media integrity | Move one imported source out of its recorded project location, select it, and use **Relink source…** first with a different file and then with an exact copy of the original bytes. Reopen the project after the successful relink. | Missing or inaccessible media is reported without becoming usable. Mismatched bytes are refused and may only be imported as new media. The matching candidate is copied into project-relative storage, retains the same asset and logical references, and reopens as available without any provider request. |
| Dropped missing-source relink | Move one imported source out of its recorded project location and select it so it is reported missing. Drag the exact original bytes back into ReelForge, then reopen the project. Repeat with different bytes that use the missing source's filename. | The exact candidate relinks the existing asset in place: Project Media contains one item, its `AssetId` and derived references remain intact, and it reopens as available. Different bytes import as a distinct asset at a collision-free project-relative path while the original remains independently missing; two active assets never share one physical path. No provider request occurs. |
| Missing-media actions and deletion | Move one imported source out of its recorded project location and select it. Verify its Project Media indicator, tooltip, context menu, and preview actions. Use **Relink** once, then choose **Delete** for a source used by at least one Saved Frame, Saved Clip, extracted asset, or composition; accept the warning and reopen the project. | The missing item shows a yellow warning triangle. Its context menu contains only **Relink source…** and **Delete from project**; the preview contains the same two actions and no implementation-language guidance. Relink uses verified relinking. Delete remains available despite dependencies, removes the item and contained file after confirmation, preserves referenced logical history as degraded state, and survives reopen without cleanup, cache pruning, or provider activity. |
| Deleted-source restoration | Delete a referenced physical source, then import an exact copy of its original bytes by file picker or drag-and-drop. Choose the deleted identity in the restoration prompt and reopen the project. Repeat by choosing **Import as new**, then use **Restore deleted source links…** on the imported copy. Also try different bytes and cancel one prompt in a multi-file import. | Restoration is always explicit and SHA-256 verified. Restoring revives the original asset identity and its Saved Frames, Clips, Audio, compositions, provenance, and historical references; it does not silently deduplicate active media. Import-as-new creates a distinct asset. An unused imported copy may be folded into the restored identity, while a referenced copy remains distinct. Different bytes are not offered as a match, and cancelling the decision leaves the entire batch unchanged. No provider request occurs. |
| Jobs and recovery | Queue a fake-provider job, switch projects, restart while it is running, then observe completion. Exercise Undo Send cancellation separately. | Global job state and elapsed time survive restart; finalization targets the owning project; queued work cancelled during Undo Send is never submitted. |
| Generation preparation | Prepare text, physical-media, Saved Frame, and Saved Clip references without confirming a paid request. | Provider capabilities constrain the form correctly; reference order/role/label/notes are preserved; no request occurs before explicit confirmation. |
| Frame and clip tools | In both Select Frame and Make Clip, navigate exact frames using the contact strip and the viewer's previous/next-frame buttons; then save/update/delete a frame, create/replay/delete a short Saved Clip, and reconstruct after clearing cache. | The contact strip and viewer remain synchronized on the same decoded PTS; viewer-button stepping remains paused and silent; derived media rebuilds from durable recipes; missing sources produce a clear failure. |
| Timeline arrangement | Add media by drag/drop, reorder, split under both split preferences, mute a segment, layer/move audio, and reopen the project. | Exact boundaries, ordering, audio placement/settings, and immutable recipe revisions persist. |
| Audition | Audition an unbaked composition, drag the player and timeline scrubbers rapidly across at least three cuts, release and resume playback, then frame-step forward and backward across a cut (including a same-source split) and play across muted segments plus independent layered audio. | Transient cross-cut seeks do not strand the player; pointer-up selects the final requested position and preserves the prior play/pause state. Frame stepping selects the adjacent segment's first/final decoded PTS without duplicating the boundary frame. Playback follows the current recipe without advancing during unrelated Project Media playback; mute/gain/pan/fade and independent audio are respected. |
| Preview and export | Preview after several timeline edits, cancel one render, retry, then export. Bake an unchanged composition, restart ReelForge, and select it again. | Preview/export materializes the current recipe; cancellation leaves no partial result; retry succeeds and export remains a normal durable file. The unchanged baked representation is restored or rematerialized without requiring another Bake; a changed recipe correctly falls back to audition. |
| Settings and platform integration | Change settings rapidly, configure/browse/auto-detect each media tool, update/remove a credential, change log/cache locations, and restart. | Atomic settings remain readable; platform defaults and overrides resolve correctly; credentials never appear in JSON/logs; configuration survives restart. |
| Cache and diagnostics | Hold one derived item in use while producing enough media to trigger eviction; inspect the configured verbose log. | Active leases are not evicted; disposable entries can rebuild; diagnostics identify failures without exposing credentials. |

The Windows shell remains the current manual presentation target. Screenshot-perfect automation is not required; extracted presenter/state logic should carry deterministic tests as it is introduced.
