# Architecture decision records

Status: active

ADRs capture durable architectural decisions. Create one when a decision changes dependency direction, a public or persistence contract, a platform/provider boundary, paid-network authorization, or release/supply-chain policy. Do not backfill routine or historical implementation choices.

Create files as `NNNN-short-title.md`. ADRs are immutable after acceptance: supersede them with a later ADR rather than rewriting the decision.

## Template

```markdown
# ADR-NNNN: Title

Status: proposed | accepted | superseded by ADR-NNNN
Date: YYYY-MM-DD

## Context

## Decision

## Consequences

## Alternatives considered

## Verification and follow-up
```
